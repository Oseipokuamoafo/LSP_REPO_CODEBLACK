Design Explanation:

The Template Method pattern is applied through the abstract Report class, which defines the fixed workflow in the generateReport() method: loadData() → formatHeader() → formatBody() → formatFooter(). The method is declared final so no subclass can reorder or skip steps. Each of the four steps is declared abstract, forcing StudentReport and CourseReport to provide their own concrete implementations while inheriting the shared skeleton. The Driver iterates a List<Report> and calls generateReport() on each element, demonstrating polymorphism — the correct subclass methods are dispatched at runtime without the Driver knowing the concrete type. This design separates the invariant algorithm structure from the variant per-report details, making it easy to add new report types without modifying the base class.
